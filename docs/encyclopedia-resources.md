# 图鉴资料与自动更新

LucimaTools 在本地保留卡片渲染、筛选、缩放、导出、动态播放器及其运行库。角色索引、详情、公共文案映射和图鉴图片从独立云端入口获取；安装包不再包含 `assets/encyclopedia/`。源码中原目录是此前版本的生成快照，当前运行逻辑不读取它，新的生成结果位于 `build/encyclopedia-bundle/`。

## 云端契约

新版通过 `/encyclopedia/latest.json` 获取资料版本，本次取景修订为 `2026.11.11-framing-r1`，包含 247 名角色。入口实际为 604 字节，包含 `schema`、`kind`、`renderer`、`version`、`index`、`ui` 和 `media`。资料引用都采用 `{path, sha256, size}`；索引和公共资料指向同目录下的 `objects/<sha256>.json`，媒体指向同版本不可变清单。

卡片页脚显示当前资料日期，本次仍为 `2026.11.11`；内部修订号用于缓存及镜头兼容。应用内查看、保存图片和批量生成成品图均传递对应版本号，后续资料更新无需修改固定日期。

- 索引保存名字、别名、属性、职业、星级、状态等列表与筛选字段，每名角色分别引用头像和详情；当前线上索引还包含轻量 `ids`、`names`、`aliases`、`pinyin` 查询表。查询表使用与成品图鉴相同的构建逻辑，支持本地按 ID、名称、别名和全拼检索，不获取详情或图片。
- 公共资料保存渲染所需的文案与图标映射，以及共用图片的哈希引用；当前为 63,644 字节。映射的原游戏资源键保留，值使用对象相对路径。
- 单人详情使用 `{schema: 1, character: {...}, media: {...}}`。`character` 保留 Ark2 处理版正式字段及本地渲染器需要的标签；`media` 只列该角色的立绘和技能资源，以逻辑路径映射到对象引用。
- 图片、骨骼和图集复用现有对象池。新增资料不重复上传已有媒体；新版不从云端加载 JavaScript。
- 入口 `schema: 1`，`renderer: 1` 为旧几何镜头，`renderer: 2` 为可见像素镜头。新版兼容两者，旧客户端保留有效旧缓存并提示更新。`renderer: 2` 另带 `media: {path, sha256, size}` 引用同版本不可变媒体快照；旧 `manifest.json` 不切换到新镜头，避免旧播放器与新静态图混用。

```text
encyclopedia/
  latest.json                    # 新版自动更新入口
  versions/<数据版本>.json         # 不可变入口快照
  objects/<sha256>.json           # 索引、公共资料、单人详情
  objects/<sha256>.png            # 头像、公共图标、立绘、技能图
  objects/<sha256>.skel
  objects/<sha256>.atlas
  manifest.json                  # 旧客户端媒体入口，继续兼容
  manifests/<媒体版本>.json
  cards/                         # 对外提供的成品 PNG 及查询表
```

图片、描述变化时按新内容生成哈希对象。版本不可原地改写；发布时先上传并核验对象与快照，最后切换 `latest.json` 并刷新入口缓存。回退时将入口切回已有快照。旧对象保留，供正在查看的旧卡片和旧版软件使用。旧媒体与成品卡片入口独立维护；本次只切换成品卡片和新版资料入口，旧媒体 `manifest.json` 保留 `2026.11.11`。

## 检查与按需下载

进入图鉴时优先显示上次有效缓存，并在后台立即检查轻量入口；无缓存时先取得入口、索引和公共资料。每次进入图鉴绕过一小时间隔，同一时间的检查合并，五秒内连续进入不重复联网。恢复前台和停留在图鉴时仍按全应用共享的一小时间隔检查，不按账号分别检查。页面不再提供同步按钮；搜索框右侧显示匹配角色数与总数。

入口使用 `Cache-Control: no-cache`，保存 ETag 并在后续请求发送 `If-None-Match`。版本不变时不重新下载角色资料和媒体；未返回 304 的服务器也只需重传小入口。失败按 2、4、8、16、30 分钟退避，图鉴可见时自动重试，再次进入可提前重试。检查及更新静默完成；已有缓存时失败继续显示缓存，无缓存且加载失败才显示错误。

列表头像沿用浏览器懒加载。搜索和筛选只使用索引，不获取全部详情。搜索支持 ID、中文名、英文名、别名和无声调全拼；旧索引缺少查询表时按 ID、名称和别名匹配，下载新版索引后启用全拼。打开卡片才取得该角色 JSON、静态立绘和技能图标；启用动态模式后才取骨骼、atlas 及其纹理。共用图片也由实际渲染需求触发。所有对象首次下载先校验大小与 SHA-256，校验失败不会覆盖有效缓存。

## 缓存与版本切换

`backend/encyclopedia.py` 在应用数据目录的 `encyclopedia-cache/` 中保存对象、入口快照、当前版本和检查状态；不写入安装目录，也不依赖浏览器端口或单个账号。Windows 和 Android 共用该实现，并使用应用的系统代理设置。

索引和公共资料全部下载并校验成功后，才原子替换当前版本入口。前端正在查看卡片、导出图片或打开状态选择框时，保留当前视图的数据版本，关闭后再应用等待中的新版。详情内存缓存使用内容哈希作为键；相同角色 ID 的新资料不会命中旧数据。

已有缓存可离线使用。首次安装离线时提示“暂时无法获取图鉴资料”；没有下载过的详情或图片不会伪造占位资料。清单、数据格式、网络或哈希异常继续使用此前有效版本。缺少官方立绘的 22 位角色继续保留空图槽。

本地 API：

- `GET /api/encyclopedia/catalog`：只读取本机已激活版本，不主动联网。
- `POST /api/encyclopedia/check`：执行按间隔检查，进入图鉴时用 `force: true` 绕过一小时间隔，仍保留五秒防抖及并发合并。
- `GET /api/encyclopedia/detail?version=...&id=Hxxx`：按指定快照下载或读取单人详情。
- `GET /api/encyclopedia/objects/<hash.ext>`：只允许访问已验证资料引用的对象，命中本机缓存时不联网。

## 来源与构建

立绘取景统一使用 Ark2 的 `tools/portrait_framing.md`。新版静态 PNG 附带约 2 KiB 的 `Hxxx.framing.json`，记录整段待机动画实际可见像素的镜头，并绑定骨骼、atlas、全部纹理和静态图 SHA-256。资源暂存校验配对；动态模式按需下载镜头并复用，不在手机上扫描动画。旧清单没有镜头时继续旧镜头；已声明镜头但损坏时保留静态回退。更换取景规则后须重建静态图和成品图，使用新的不可变资源版本，不能覆盖已发布快照。

同日取景修订使用 `2026.11.11-framing-r1` 一类的唯一资源版本；卡片页脚仍显示 `2026.11.11`。发布计划只切换成品图与新版资料入口，保留旧媒体入口，所有引用的新文件仍先上传并核验。

源资料继续来自当前 Ark2 项目的官方表和处理版 `out/assets/团员/资料`。不依赖旧 OpenRubi 项目，也不自行编写或缩写游戏文案。

日常使用统一构建入口，资源版本独立于软件版本。默认从同级 `ark2/` 读取当前提取资料，可用 `--ark2-root` 指定其它位置：

```powershell
.\build-encyclopedia.bat --version <新资源版本> --cards
```

此命令依次整理资料、头像和媒体，生成云端资料，并使用当前前端渲染器生成整套成品 PNG 和查询表。头像直接来自本次 Ark2 提取源，不依赖安装包内的旧头像。构建需要 Pillow 和 pypinyin；生成卡片还需要 Playwright（Chromium）。

- 省略 `--cards`：只更新云端资料与媒体，已有成品卡片入口不参与此次发布。
- 增加 `--reuse-media`：复用现有媒体清单，适合没有图片变动的资料更新；新资料引用的媒体仍必须完整存在。
- `--from-existing --cards`：只校验当前已有产物并生成发布计划，不重新提取或渲染，可省略 `--version`。
- `--source-gaps <缺图清单.json>`：仅在已核实官方技能图缺源时使用。清单绑定 catalog 版本和 SHA256，逐项保留原始图片路径与原因；原角色引用不改写，媒体清单和单人详情另记缺口。成品卡保留空图槽，其它缺图或解码失败仍中止构建。没有此参数时仍要求引用的技能图全部存在。

中间结果写入 `build/encyclopedia/<资源版本>/`，最终文件仍位于 `releases/encyclopedia/`。全部引用文件、角色集合和版本快照校验通过后，才生成该目录的 `.release-plan.json`；它记录此次要发布的文件与入口，不上传云端。构建命令不联网、不上传文件。

发布工具在本机 `deploy/encyclopedia/` 维护，不随软件源码仓库分发。先预演，再执行上传：

```powershell
.\deploy\encyclopedia\publish.bat --dry-run
.\deploy\encyclopedia\publish.bat
```

预演重新校验本地发布计划及全部文件，不联网、不读取云凭据。实际发布只处理计划引用的文件，先上传并校验不可变对象及其公开下载内容，再按计划切换必要入口；`latest.json` 最后切换。可见像素镜头版本保留旧媒体入口，只发布新媒体快照、成品卡片和新版资料入口。中断状态与入口备份保存在 `deploy/encyclopedia/state/`，重跑命令继续处理缓存刷新。图鉴上传复用本机私有配置，独立于软件发布通道。

底层 `build_encyclopedia.py`、`stage_encyclopedia_cdn.py`、`build_cloud_encyclopedia.py` 和 `build_encyclopedia_cards.py` 继续供单步构建及排查使用。角色数量由生成索引决定，无需为新角色修改发布脚本。不同内容仍须使用新资源版本，不覆盖已发布快照。

本地服务地址沿用忽略提交的 `encyclopedia-endpoint.json` 或环境变量 `LUCIMA_ENCYCLOPEDIA_URL`。配置可以指向 `latest.json`；已有 `manifest.json` 配置会解析为同目录下的 `latest.json`。软件更新检查与图鉴检查彼此独立，`start.bat` 也支持图鉴更新。

Windows spec 与 Android `copyWebAssets` 均排除 `assets/encyclopedia/**`。其它业务所需的角色头像、属性和职业小索引仍由公共游戏资源提供；基本信息页职业筛选读取独立的 `assets/role_jobs.json`，不再读取图鉴索引或等待图鉴网络请求。
