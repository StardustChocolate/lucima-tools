# 游戏数据自动更新

软件直接查询游戏官方公告和 Android Addressables 目录，下载并解析官方数据包，不依赖资源提取工作站或我们自己的云端发布。

- 应用启动时检查；日常跟随软件本体更新检查，共用约每小时一次（45～75 分钟）的节奏。源码测试环境没有软件版本轮询，使用相同的小时策略。登录公告明确出现新资源版本时会立即检查，多账号共享一套数据和下载缓存。
- 无更新时只查询公告和目录的 `.hash`；目录名称相同但指纹改变，也会重新检查。
- 有更新时只获取 `staticdata`、`text`、`localization/chs.asset`，按包指纹复用缓存，不下载图片、模型、音频。
- 内置标准库 UnityFS/LZ4 读取器只支持所需 TextAsset 和已验证的简中补充结构。按块解压到临时文件，避免同时展开并保留十种语言；没有增加 Android 原生解包依赖。
- 取出全部静态表及 CHS，优先使用主文本，只补入另一套简中系统的独占键；不推测或改写游戏文案。

## 数据范围

生成 15 份运行 JSON：关卡与战斗定义、技能静态索引、活动及公共参数、角色属性/职业、物品名称/稀有度/分类、装备引用、活动名称、商品限购与团长商品价格，以及团员商店、资源支持和周任务配置。投票活动的完整候选名单、选票与任务配置编入 `assets/game_config.json`。

运行构建与离线构建共用 `backend/build_battle_metadata.py`、`backend/game_table_dsl.py` 和 `backend/guild_data_build.py`。`tools/` 原入口继续可用。

本流程更新运行数据。角色图鉴的完整详情、动态/静态立绘及成品卡片继续沿用独立的图鉴更新服务；本地协议代码、任务流程及未知战斗机制需要软件更新。

## 启用与恢复

数据保存在应用数据目录的 `game-data/`，与安装目录及用户账号配置分开：

```text
game-data/
├── active.json                    # 当前及上一可用版本
├── update-state.json              # 检查状态、下次时间及失败原因
├── bundles/<官方指纹>.bundle      # 官方原包缓存
├── bundles/<官方指纹>.json        # 本地 SHA256 与大小记录
└── versions/<目录名>-<指纹前缀>-b<构建版本>/
    ├── manifest.json              # 来源、构建报告、各产物 SHA256
    ├── assets/…                   # 更新后的运行数据
    └── backend/…                  # 更新后的映射表
```

先完整生成并校验数据，再原子替换当前入口。下载/转换期间再次核对公告与目录指纹，防止版本中途变化。官方维护期间只准备数据，等维护结束后启用。失败保留原版本，按当前检查节奏重试；启动时当前缓存损坏则尝试上一版本，最后回退安装包数据。

软件增加数据构建规则时提升构建版本；即使官方目录没有更新，也会复用已缓存的原包重新生成数据，避免旧缓存缺少新增功能配置。

任务及 API 请求使用固定的数据快照；普通数据更新完成后，下次读取使用新版本。新功能应通过 `runtime_data.read_json()` 读取、使用 `runtime_data.cached` 缓存；跨多个读取步骤的任务用 `runtime_data.pin()` 或 `@runtime_data.pinned` 固定版本。

官方公告明确返回 `IsOpen=false/0`，或任一游戏接口返回 `Server Maintain` / `Server Maintain_Server Maintain` 时，全局停止所有账号的任务并阻断后续游戏请求，同时取消自动推关、深渊战斗和佣兵团长任务；已发出的请求仍需等待返回。普通请求、登录、开发者控制台和公开公告查询共用维护判断，兼容 JSON 消息包装。

维护期间切换到每 5 分钟检查一次公告和目录指纹；有新资源即下载并准备，网络/下载/转换失败也继续使用 5 分钟间隔，不因软件版本检查或重复维护响应而延后。该快速轮询只查询游戏官方信息，不提高软件版本检查频率。缺失/无效字段及网络失败不视为维护结束；已在途的开放公告不能覆盖后来收到的维护响应。

只有公告明确返回 `IsOpen=true/1` 才解除维护门禁，并恢复跟随软件版本检查的小时节奏。每个受影响的账号在该维护周期自动重登一次，不依赖“断联后自动重登”开关；成功后按登录任务 → 佣兵团状态同步 → 其余自动任务的顺序继续，保留原任务开关。手动扫荡、战斗、商店刷新等操作保持停止，不重放；维护前已排队的请求也不能在恢复后继续发送。重登失败则继续停止，等待手动重登；注销账号不会被恢复。连接胶囊和账号状态灯会提示维护/等待重登。

关于页的“游戏数据”显示当前版本和更新状态，并提供手动检查按钮。检查结果使用已有气泡提示。

接口：`GET /api/resources/status`、`POST /api/resources/check`。状态接口只读本地缓存，检查接口唤醒后台更新并立即返回。
