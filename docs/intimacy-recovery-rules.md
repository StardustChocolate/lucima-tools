# 亲密度与借装恢复规则

更新日期：2026-11-05。对应实现：`backend/intimacy.py`、`backend/abyss_loadout.py`。

## 先同步，再判断

1. 开始亲密度任务前，完整登录同步当前账号的角色实例、装备、羁绊和亲密度。角色实例编号与英雄图鉴编号不是同一种编号。
2. 恢复借装也必须先同步。服务器缺少相应列表字段，不等于空背包、角色删除或物品丢失；保留恢复记录，提示同步未完成。
3. 发现已拥有的新英雄缺少职业、初始星级等静态资料时，自动更新游戏资源，再读取账号信息继续。下载失败等待自动重试，可中止，不能悄悄漏掉新英雄。
4. `No Role` 是服务器的业务拒绝，不直接等于“游戏出了新角色”。收到后完整同步，再核对角色实例和资产当前归属。

## 亲密度培养规则

- 在虚构深渊第1关刷取；未首通时先按深渊规则完成首通。
- 只统计实际拥有的初始四星、五星英雄，同图鉴编号的重复实例共用亲密度，不重复加入培养队列；升星后的三星英雄不因此变成培养目标。
- 每半队默认一名输出主角色、最多三名陪刷。自动主输出从符合当前职业、属性和关卡规则的 Lv60 输出角色中选择；手选主角色保持用户选择。
- 新陪刷批次优先一名角色等级最高者，再补角色等级最低者。同等级时以亲密度等现有排序打破平局。每半队本批全部达到亲密度10级后才换下一批。
- 自动主输出按半区分别统计失败：连续失败两次更换该半区主输出；单主输出更换达到五次后尝试双主输出，小角色池可提前尝试双主。网络错误和结算未知不算已确认战败。手选主角色不被自动替换。
- 只有符合配装条件的角色才自动借装，主输出优先，装备互不重复；隔离资产及其持有者配装不参加新配装。亲密度进度以服务器确认为准。
- 深渊胜利的 `SceneRewardData` 已包含权威 `LineRoleDatas`，直接合并到本地快照，不再每场完整重登；只有结算帧没有携带亲密度数据时才回退到完整同步。轮次之间不再加入人为等待，战斗连续进行。
- 游戏客户端“战斗 9 倍速”是本地内存补丁（写入 `BattlePlayerSetting.NowSpeed=9.0`），只缩短 Unity 动画；本工具是协议客户端，不加载游戏客户端，无法复用该补丁。协议层已在服务器每次要求行动时立即提交，没有动画等待可再缩短。

## 借装及归还规则

1. 操作前按账号、资产实例保存原归属，先写持久记录再穿戴。主角色、上下半陪刷有各自记录；合并恢复按最早原归属处理，不能归还给中间借用者。
2. 逐件归还。一件失败不妨碍其他装备或羁绊处理。已确认归还的不重复请求；响应丢失先回读，不盲目重放。
3. 返回 `No Role` 时先完整同步；只有明确收到这类拒绝且同步成功，才允许再尝试一次。旧角色编号仅在保存的图鉴身份对应当前唯一实例时修正；有多个同名实例不能猜。
4. 原角色确实无法定位、原部位冲突或归还再次被服务器拒绝时，尝试卸回背包。必须确认空穿戴归属，才能显示“已卸下”。已经不存在的资产经服务器回读确认后记为缺失。
5. 连卸下也失败，或其他操作失败但服务器当前状态可确认时，将单件保留原归属并隔离。隔离成功后移出阻塞启动的记录，亲密度用其他可用资产继续。隔离记录写入失败不得先删除原记录。
6. 隔离不是归还成功。隔离物品不能再次借用或被自动卖掉；同一持有者的配装也要保护，避免穿戴新物品间接顶下隔离物品。背包整理保留原有的未恢复资产保护。
7. 正常收尾不反复重试本轮已经隔离的旧问题。再次启动或用户主动恢复时可重新核对；新隔离项与旧记录合并，不能覆盖旧原归属。
8. 网络完全不可读时，保留原记录并停止新增借装；恢复联网后再次启动会先处理记录。缺少足够可用角色或装备时明确提示原因，不承诺无资源也能继续战斗。
9. 中止不取消归还；当前可处理的资产仍收尾。结果区分已归还、已卸下、已缺失、仍隔离四种状态。

## 本次故障证据与原因

用户提供的开发者日志记录：

- 08:42:48 启动亲密度。
- 08:42:56，`ArtifactHandler.UnEquip` 返回 HTTP 200，响应正文为 `No Role`。HTTP 200 不代表游戏操作成功。
- 08:43:01，重新登录后对同一羁绊卸下仍收到 `No Role`。
- 08:43:09，旧代码记录“部分装备或羁绊未确认归还，已尝试并清除待归还记录”。
- 截图同时显示 `module 'backend.abyss_loadout' has no attribute '_no_role'`。

核对源码后确认三处实现脱节：异常处理仍引用已删除的函数；`restore_many` 接受隔离参数却不执行隔离；未确认资产被清除后仍可再次进入配装，隔离记录又曾被算作阻塞启动的记录。这些问题叠加，导致归还问题反复触发并直接退出亲密度。

已改为公开的 `is_no_role` 分类入口，恢复逐件核对、确认卸下与持久隔离，并补齐换下一批陪刷时的同类恢复路径。暂时性 `No Role` 恢复后，即使没有产生新隔离项，也允许重新配装继续；相同状态不会无限重试。

日志没有记录登录响应中的完整角色列表，因此无法证明这次服务器拒绝究竟来自新角色、失效角色编号还是服务器残留归属。新角色静态资料缺失和账号角色列表过期已分别覆盖验证，不将推测写成根因结论。

## 2026-11-05 追加：关卡临时 503 与自动推关的 No Role 恢复

- `HTTP 503 upstream connect error / disconnect/reset before headers` 是游戏关口（`Router/RouterHandler.ashx` 前面的网关）在后端重启或短暂不可用时的纯文本响应。请求没有进入游戏后端，因此重放不会重复扣费或重复操作。`GameClient` 对非 JSON 的 502/503/504 自动重试 2 次（约 0.4s、0.8s）；仍失败时抛 `GameUnavailable`，亲密度任务按可重试的传输错误等待后继续，而不是结束任务。
- 只重放明文关口错误。服务器返回 JSON 的 5xx 可能已经提交，保持不重试，交由调用方核对服务器状态。
- 虚构深渊自动推关在配装阶段收到 `No Role` 时，完整同步账号、把服务器拒绝的借装隔离并保留原始归属，再用其他资产重新配装；每次运行最多重试 2 次，不会无限循环。收尾归还同样把已确认被拒的资产隔离后继续；只有账号状态无法读取时才保留记录并停止推关。
- 回归新增 `tools/test_gateway_unavailable.py` 与 `tools/test_abyss_auto.ProgressionNoRoleIsolation`，并保持本文件所列测试清单全部通过。
